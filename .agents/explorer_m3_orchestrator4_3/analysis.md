# Comprehensive Analysis: Mobile Client Flow (Milestone 3)

## 1. Executive Summary

Milestone 3 addresses the modernization of the mobile client booking experience in ArenaHub. The primary goals are:
1. **R1: Remove Cash & Auto-Deduct Wallet**: Eliminate manual payment method selection (`PaymentMethodSelector.tsx`), automatically deduct available wallet balance from total/deposit amount, and route remaining balance through Paymob (or skip Paymob if covered 100% by wallet).
2. **R2: Multi-Slot Booking UI**: Enable users to select multiple continuous or non-continuous slots on the same date via an interactive `SlotPicker.tsx`, with visual badges, slot counter, clear selection, and group checkout submission.
3. **R3: Minimum Deposit Per Slot**: Read `venue.minimumDepositAmount`, compute deposit required as `selectedSlots.length * minimumDepositAmount`, and display both total cost and required deposit in `BookingSummaryFooter.tsx`.
4. **R4: Fix Booked Slots Availability Bug**: Fix timezone parsing and multi-hour interval lockout `[startTime, endTime)` in `useBookingFlow.ts` and `dateSlotGenerator.ts`.
5. **TypeScript & Type System Harmonization**: Update mobile interfaces (`types/index.ts`, `venue.schema.ts`, `booking.dto.ts`) to align with NestJS Mongoose backend contracts.

## 2. End-to-End User Interaction Flow Analysis

### 2.1 Screen Entry & Venue Data Loading
- **Entry File**: `app/pitch/[id].tsx`
- **Hook**: `useVenue(id)` fetches the live venue details from `GET /api/v1/venue/:id`.
- **Loading State**: Displays themed `ActivityIndicator` and localized loading text (`t('venue.loadingVenue')`).
- **Initialization**: Once loaded, passes `venue` to `PitchDetailsContent` which invokes `useBookingFlow(venue)`.

```
[Pitch Details Screen: app/pitch/[id].tsx]
   │
   ├──> useVenue(id) -> Fetches Live Venue Data
   │
   └──> useBookingFlow(venue)
          ├──> generateFutureBookingDates (30-day forecast)
          ├──> bookingApi.getAvailability (initial lockout)
          ├──> socketService.joinVenue (real-time slot locks)
          └──> loadWallet (fetches customer wallet balance)
```

### 2.2 Date Selection (`DateSelector.tsx`)
- Displays horizontal date strip generated by `generateFutureBookingDates(venue, 30)`.
- Selecting a date updates `selectedDateIndex` and `currentDate` in `useBookingFlow`.
- Changing dates resets or preserves selected slots scoped to that date.

### 2.3 Slot Selection (`SlotPicker.tsx`)
- Renders available operating hours between `venue.startWorkingHours` and `venue.endWorkingHours`.
- Dynamic pricing per slot computed via `calculateSlotPrice(venue, hour)` (accounting for `customHourPrices`).
- Real-time availability check:
  - Past slots for today (`isPastToday = now.getHours() >= h`) are disabled.
  - Booked or held slots from `lockedSlots` (`${date}_${hour}`) are disabled and marked "Booked" / "محجوز".
- **Multi-Slot Selection UX**:
  - Tapping an available slot toggles its inclusion in `selectedSlots: HourlySlot[]`.
  - Multiple non-continuous slots on the same date can be selected (e.g. 10:00-11:00 AM and 03:00-04:00 PM).
  - Selected slots are highlighted in active theme color (`#22c55e` / `#16a34a`) with checkmark / selection counter badges.
  - A "Clear All" action is provided when $\ge 1$ slots are selected.

### 2.4 Pricing & Deposit Computation (`BookingSummaryFooter.tsx`)
- **Total Price**:
  $$T = \sum_{s \in \text{selectedSlots}} s.\text{price}$$
- **Minimum Deposit Calculation**:
  If `venue.minimumDepositAmount > 0`:
  $$D_{\text{unit}} = \text{venue.minimumDepositAmount}$$
  $$D_{\text{total}} = \min(\text{selectedSlots.length} \times D_{\text{unit}}, T)$$
  If no minimum deposit configured: $D_{\text{total}} = T$.
- **Auto-Deduction from Wallet**:
  $$W_{\text{deduct}} = \min(\text{walletBalance}, D_{\text{total}})$$
  $$P_{\text{due}} = D_{\text{total}} - W_{\text{deduct}}$$
- **Footer Display**:
  - Slot counter: "X Slots Selected".
  - Total Price: "$T$ EGP" with Deposit breakdown "Deposit Due: $D_{\text{total}}$ EGP ($N \times D_{\text{unit}}$ EGP)".
  - Wallet applied: "-$W_{\text{deduct}}$ EGP".
  - Paymob Card remainder: "$P_{\text{due}}$ EGP" (or "100% Covered by Wallet").
  - Primary CTA button: "Book $N$ Slots • Pay $D_{\text{total}}$ EGP".

### 2.5 Checkout Submission Flow
- **Authentication Check**: If user is unauthenticated, saves `pendingBooking` (including `slots`) to `AuthContext` and redirects to `/(auth)/login`.
- **Payment Method Determination**:
  - If $P_{\text{due}} === 0$: `paymentMethod = PaymentMethodEnum.wallet`.
  - If $P_{\text{due}} > 0$: `paymentMethod = PaymentMethodEnum.paymob`.
- **API Dispatch**:
  Calls `POST /api/v1/booking` with payload:
  ```json
  {
    "venueId": "64e8b0a1f2b4c10012345678",
    "date": "2026-08-25",
    "slots": [
      { "startTime": 18, "endTime": 19 },
      { "startTime": 21, "endTime": 22 }
    ],
    "paymentMethod": "wallet", // or "paymob"
    "idempotencyKey": "uuid-v4"
  }
  ```
- **Response Handling**:
  - **Wallet Full Payment** ($P_{\text{due}} = 0$): Server creates confirmed booking group, returns `groupId` and `bookings`. Mobile shows `BookingResultModal` with `SUCCESS`, invalidates TanStack Query caches, and reloads wallet.
  - **Paymob Remainder** ($P_{\text{due}} > 0$): Server creates pending booking group and returns Paymob `clientSecret` and `publicKey`. Mobile opens `PaymobWebViewCheckout`.
  - **Paymob Success**: Client polls `GET /api/v1/booking/:id` or receives socket `bookingConfirmed`, then presents `BookingResultModal`.
  - **Paymob Failure/Cancellation**: Automatically invokes `PATCH /api/v1/booking/:id/cancel` to release locked slots in Redis/DB.

### 3.4 `useBookingFlow.ts`
- **Location**: `features/bookings/hooks/useBookingFlow.ts`
- **Required Changes**:
  1. Replace `selectedSlot` state with `selectedSlots: HourlySlot[]` (default `[]`).
  2. Implement `toggleSlot(slot: HourlySlot)` and `clearSelectedSlots()`.
  3. Reset `selectedSlots` on date change (`selectedDateIndex` change).
  4. Fix multi-hour booked slot lockout bug in `bookingApi.getAvailability` and socket listeners:
     ```typescript
     unavailable.forEach((b) => {
       const d = typeof b.date === 'string' ? b.date.split('T')[0] : new Date(b.date).toISOString().split('T')[0];
       const start = b.startTime;
       const end = b.endTime || (start + 1);
       for (let h = start; h < end; h++) {
         initialLocks[`${d}_${h}`] = true;
       }
     });
     ```
  5. Compute deposit and wallet values:
     ```typescript
     const totalPrice = useMemo(() =>
       selectedSlots.reduce((sum, s) => sum + (s.price ?? venue.defaultHourPrice), 0),
       [selectedSlots, venue.defaultHourPrice]
     );
     const minimumDeposit = venue.minimumDepositAmount ?? 0;
     const depositRequired = useMemo(() =>
       minimumDeposit > 0 ? Math.min(selectedSlots.length * minimumDeposit, totalPrice) : totalPrice,
       [minimumDeposit, selectedSlots.length, totalPrice]
     );
     const walletDeduction = useMemo(() =>
       Math.min(walletBalance, depositRequired),
       [walletBalance, depositRequired]
     );
     const paymobRemainder = useMemo(() =>
       depositRequired - walletDeduction,
       [depositRequired, walletDeduction]
     );
     ```
  6. Update `handleBookNow` to pass `slots: selectedSlots.map(...)` in `bookingApi.createBooking`.
